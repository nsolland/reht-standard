# Contributing

REHT Standard is a public specification, not a production-code repository.

Discussion, issues, papers, workshops and publisher review are welcome proposal/evidence surfaces. They are not normative by themselves. Normative meaning changes only through an accepted, versioned specification change under [`GOVERNANCE.md`](GOVERNANCE.md).

Contributions must be submitted through pull requests and include:

- problem statement and stable issue/proposal reference;
- proposed normative or non-normative change;
- compatibility class: major, minor or patch;
- security impact;
- affected schemas, profiles and examples;
- required positive/negative conformance cases where behavior changes;
- migration notes where applicable;
- external evidence/references where relevant;
- proposed target specification version.

Normative language uses MUST, MUST NOT, SHOULD, SHOULD NOT and MAY as defined by RFC 2119 and RFC 8174.

Do not submit private VALO source code, customer information, credentials, unpublished patent material, internal thresholds or proprietary evaluation logic.

A private implementation or experiment may motivate a public standard proposal, but implementation existence does not make the proposal normative.

Publisher, journal, conference or external standards review comments should be converted into traceable issues/PRs before changing normative text. This preserves provenance between external discussion and the executable conformance surface.

By submitting a contribution, you agree that it may be licensed under Apache License 2.0 and that you have the right to submit it.
